# 方法 pipeline：各部分的输入输出

本文按"数据怎么流动"整理整个方法，供审查方案用。设计理由见 `system_overview.md`，命令见 `../PIPELINE.md`。

- 仿真动力学就用 Stonefish 现有的模型，不做修正。
- 下文的数字都是代码里的当前默认值。最后一节列出了值得审查的设计点，以及改动位置。
- 最后更新：2026-11-16。

---

## 0. 总览

```
══════════════════════ 训练 ══════════════════════

USIM 数据集 ──①生成参考轨迹──▶ 参考轨迹（50 Hz 全身状态）
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼ （可选）                           ▼
          ②世界模型离线预训练                 ③在线训练循环（反复执行）
            → world_model.pt ───初始化───▶      a. Stonefish 采集 → 回放缓存
                                                b. 世界模型更新
                                                c. 策略在世界模型里想象 32 步，BPTT 更新
                                                d. 按回报调整重置分布
                                                      │
                                                      ▼
                                 actor.pt（策略）  world_model.pt  critic.pt

══════════════════════ 推理 ══════════════════════

传感器读数 + 位姿估计 + 参考轨迹 ──▶ 策略（actor.pt）──▶ 8 个推进器指令 + 4 个臂关节目标 + 1 个夹爪目标
              （每 0.02 s 一次；世界模型、价值网络、奖励在推理时都不用）
```

| | 输入 | 输出 |
|---|---|---|
| **整个训练** | USIM 数据集（只用 HF 版）；Stonefish 场景 `stonefish_bench/scenarios/rov_alpha5.scn`；配置 | `actor.pt`（部署用）、`world_model.pt`、`critic.pt`、训练日志 |
| **推理（每 0.02 s）** | IMU、DVL、关节编码器、深度计、水平定位、航向，上一步动作，参考轨迹 | 8 个推进器设定值 [−1, 1]，4 个臂关节目标角，1 个夹爪开合目标 |

## 1. 统一的数据格式

坐标系就是 Stonefish 的：世界系 NED（z 向下），机体系 FRD（前-右-下）。四元数 wxyz。控制频率 50 Hz（dt = 0.02 s），每个控制步含 2 个物理步。

### 1.1 关节顺序

状态顺序为 `axis_e, axis_d, axis_c, axis_b, axis_a, rs1_139_joint, rs1_130_joint`：
- 前 4 个是臂关节；
- `axis_a` 是夹爪开合；
- 后两个是两根手指，始终等于 0.83 × `axis_a`。

### 1.2 各向量的布局

| 名字 | 维数 | 布局 | 谁用 |
|---|---|---|---|
| **full_state** 完整状态 | 27 | 航行器位置 3、姿态 4、关节角 7、世界系线速度 3、世界系角速度 3、关节角速度 7 | 回放缓存、奖励 |
| **rep_state** 身体状态 | 24 | 深度 1、重力方向（机体系）3、机体系线速度 3、机体系角速度 3、关节角 7、关节角速度 7 | 世界模型输入、价值网络 |
| **aux** 位姿 | 7 | 航行器位置 3、姿态 4 | 世界模型积分 |
| **sensor** 传感器读数 | 23 | 重力方向 3、角速度 3、DVL 速度 3、关节角 7、关节角速度 7 | 策略 |
| **actor obs** 策略观测 | 36 | sensor 23 + 上一步动作 13 | 策略 |
| **goal** 参考窗口 | 230 | 见 1.3 | 策略、价值网络 |
| **action** 策略动作 | 13 | 见 1.4 | 世界模型、仿真 |
| **sim action** 仿真指令 | 15 | 8 个推进器设定值 + 7 个舵机目标（舵机顺序 `e, d, c, b, a, rs1_130, rs1_139`） | Stonefish |

**关节角速度的定义**：上一步的平均速度 (q_k − q_{k−1}) / 0.02，每条参考片段的第一帧取 0。参考轨迹、仿真采集、世界模型都用这个定义。

### 1.3 goal 参考窗口（230 维）

设 t 是"这一步之后应该到达的参考帧"。取 t, t+5, …, t+45 共 10 帧，即未来 0.9 s；超出当前片段末尾的帧用最后一帧代替。

| 段 | 维数 | 内容 |
|---|---|---|
| 关节目标 | 140 | 每帧 [参考关节角 7, 参考关节角速度 7] |
| 相对位置 | 30 | 每帧：参考航行器位置相对当前位置，在当前机体系里表示，Rᵀ(p_ref − p̂) |
| 相对姿态 | 60 | 每帧：参考航行器姿态相对当前姿态 Rᵀ·R_ref，取旋转矩阵前两列（6 维） |

- p̂ 是**测量的**位置。策略的目标用带误差的位置算，价值网络的目标用真实位置算，两者维数相同。
- 原版 SuperMimic 的策略看不到"相对位置"这 30 维，我们的策略看得到。

### 1.4 action 策略动作（13 维）

| 段 | 维数 | 含义 | 换算成仿真指令 |
|---|---|---|---|
| 推进器 | 8 | `FrontRight, FrontLeft, BackRight, BackLeft, DiveFrontRight, DiveFrontLeft, DiveBackRight, DiveBackLeft` | clip 到 [−1, 1] 后直接下发 |
| 臂关节 | 4 | e、d、c、b 的**相对**目标 a ∈ [−1, 1] | 舵机目标 = 当前角 + 0.01 × clip(a)，即每步最多走 0.01 rad |
| 夹爪 | 1 | 开合目标 a ∈ [−1, 1] | `axis_a` 目标 = (clip(a) + 1)/2 × 0.015 m，手指目标 = 0.83 × 该值 |

策略网络的原始输出不做截断，截断发生在换算成指令时（仿真里和世界模型里一样）。超出 [−1, 1] 的部分由"动作越界惩罚"拉回。

## 2. 各组成部分的输入输出

### 2.1 参考轨迹生成【已实现】 `tools/usim_make_refs.py`

| | 内容 |
|---|---|
| 输入 | USIM 每条 episode：推进器指令（10 Hz）、机械臂关节角（10 Hz）、第 0 帧的深度（压力）、横滚俯仰（比力）、DVL 速度、角速度 |
| 做法 | 从第 0 帧状态出发，在 Stonefish 里开环重放推进器指令（零阶保持到 50 Hz）。机械臂有两种：`usim` 复现记录的关节运动，`random` 在限位内随机点到点运动且不碰艇体 |
| 输出 | 每帧的 `root_pos_w`(3)、`root_quat_w`(4)、`root_lin_vel_w`(3)、`root_ang_vel_w`(3)、`joint_pos`(7)、`joint_vel`(7)、`actions`(15，产生下一帧的仿真指令)、TCP 位姿；片段分界 `motion_ends` |
| 规模 | 训练集 3469 条片段、38.5 h；测试集 1037 条、11.5 h（`data/refs/usim_{train,test}_v1`） |

第 k 帧是执行 `actions[k]` 之前的状态。

### 2.2 正运动学【已实现】 `rovmimic/fk.py`、`rovmimic/motion.py`

| | 内容 |
|---|---|
| 输入 | 航行器位置、姿态、世界系线速度和角速度，关节角 7、关节角速度 7 |
| 输出 | 10 个点的世界系位置、姿态、线速度、角速度：`base_link`、`m2_1_1_link`、`m2_joint_link`、`m2_1_2_link`、`ee_base_link`、`tcp`（奖励用前 6 个），以及 `m1_link`、两根手指、指尖（艇体检查用，`m2_joint_link` 起往后 8 个） |
| 用在 | 参考轨迹的连杆状态（`ROVMotion.body_state`），以及仿真状态和世界模型预测状态的连杆状态。三者用同一个函数 |

### 2.3 奖励和失败判定【已实现】 `rovmimic/tracking.py`

| | 内容 |
|---|---|
| 输入 | 这一步之后的 full_state 27；这一步的动作 13 和上一步的动作 13；参考帧 t 的连杆状态（正运动学）和参考关节角 |
| 输出 | 每步奖励（标量，满分 0.16）；各项明细；误差：航行器三维位置误差、姿态转角、艇体侵入深度、TCP 误差 |
| 失败 | 仿真里误差超阈值就判失败（0.5 m、0.8 rad、3 cm）；世界模型里用平滑概率 sigmoid((max(误差/阈值) − 1)/0.05) |

各奖励项的权重见 `system_overview.md` 4.5。仿真和世界模型调用同一个函数。

### 2.4 仿真环境【已实现】 `rovmimic/env.py`（底层 `rovmimic/vec_sim.py`）

N 个环境分给多个进程，每个进程跑一个 Stonefish。

| | 内容 |
|---|---|
| 输入 | 策略动作 (N, 13) |
| 输出 | 观测：full_state (N, 27)、actor obs (N, 36，**不含噪声**)、goal (N, 230，用真实位置算，只用来确定维数)；奖励 (N,)；结束标志 (N,)；附加信息：其中正常结束的（片段放完或超时）、各项奖励和误差的统计 |
| 环境内部保存 | Stonefish 真实状态（含舵机步末读数）、上一步平均关节速度、上一步动作、当前参考帧 t、回合步数、水平定位偏差 |

每一步的处理顺序（与 mjlab 相同）：
1. 动作 → 仿真指令（1.4），推进 0.02 s。
2. 关节角速度 = Δq / 0.02，拼出 full_state。
3. 用参考帧 t 算奖励和失败判定（2.3）。另外两种正常结束：t 是片段最后一帧，或者回合满 500 步（10 s）。
4. 所有环境 t += 1。
5. 结束的环境重置：
   - 按重置分布（2.9）抽参考帧 f，状态设为参考第 f 帧加小扰动；
   - t = f + 1，上一步动作清零，重新抽水平定位偏差。
6. 水平定位偏差随机游走一步。

另外提供 `position_noise()`：这一步的位置测量误差 (N, 3)。水平是缓慢漂移的偏差，竖直是深度计噪声。

### 2.5 世界模型【已实现】 `rovmimic/representation.py`

| | 内容 |
|---|---|
| 输入 | aux 7、rep_state 24、动作 13（原始输出）、仿真参数 1（不做域随机化，恒为 0） |
| 输出 | 下一步的 aux 7、rep_state 24 |
| 网络 | 输入 = [归一化 rep_state 24, 归一化 clip(动作) 13, 仿真参数 1] = 38 维 → 3 层 2048（LayerNorm + GELU）→ 6 维 |

一步的计算：
1. 网络输出 × 固定尺度 (0.002, 0.002, 0.002, 0.004, 0.002, 0.01)，得到当前机体系下的线速度和角速度变化量 Δv、Δw。
2. 航行器积分：
   - 位置 += R(v + 0.75 Δv) × 0.02；
   - 姿态按 R(w + 0.75 Δw) × 0.02 转动；
   - 新速度 = 旧速度 + 变化量，再换到新的机体系；
   - 深度、重力方向由新位姿算出。
3. 机械臂和夹爪按舵机公式：
   - 臂关节 q + 0.01 × clip(a)；
   - 夹爪和手指 q + clip(目标 − q, ±最大速度 × 0.02)；
   - 关节角速度 = Δq / 0.02。

网络只负责第 1 步的 6 个数，其余都是公式。

### 2.6 想象环境【已实现】 `rovmimic/wm_env.py`

策略训练时，用世界模型代替仿真。批量 B = 4096。

| | 内容 |
|---|---|
| 重置输入 | 从回放缓存抽 B 个真实状态：full_state、上一步动作、参考帧 t、仿真参数 |
| 每步输入 | 策略动作 (B, 13) |
| 每步输出 | 策略观测（actor obs 36 **加噪声**，goal 230 用带误差的位置算）；价值网络输入 255；奖励 (B,)；失败概率 (B,) |

- 每段想象开始时，在 ±0.1 m 内抽一个水平定位偏差，段内不变。
- 每步加新的深度计噪声和传感器噪声。
- 参考帧每步 +1，到片段末尾就停住，不重置。

### 2.7 策略（actor）【已实现】 SuperMimic 原版的 `MultiEncoderAE`，只保留"动作跟踪"一个任务

| | 内容 |
|---|---|
| 输入 | actor obs 36（传感器 23 + 上一步动作 13），goal 230 |
| 输出 | 动作 13 |
| 网络 | goal → 归一化 → 编码器 (2048, 1024, 512, 256) → 32 维，经 tanh；[32, 归一化 actor obs 36] → 解码器 (2048, 1024, 512, 256) → 13 |

归一化统计在网络内部，部署时直接喂原始读数。

### 2.8 价值网络（critic）【已实现】只在训练中用

| | 内容 |
|---|---|
| 输入 | rep_state 24（真实）+ goal 230（用真实位置算）+ 仿真参数 1 = 255 |
| 输出 | 状态价值 V（标量，上限 0.16 / (1 − 0.99) = 16） |
| 网络 | (256, 128) |

### 2.9 回放缓存和重置分布【已实现】 SuperMimic 原版

**回放缓存**：每个环境存最近 1000 步。每条转移包含：

| 字段 | 维数 |
|---|---|
| 这一步之前的 full_state | 27 |
| 动作（含探索噪声的原始输出） | 13 |
| 上一步动作 | 13 |
| 参考帧 t | 1 |
| 失败标志、正常结束标志 | 各 1 |
| 仿真参数 | 1 |

**重置分布**（`ReturnSampler`）：
- 把参考轨迹按 0.2 s 分箱，用仿真里实际拿到的回报估计每箱的价值；
- 每 20 步更新一次分布，回报低的箱被抽中的概率更高；
- 另外保留 50% 均匀探索、10% 历史均衡。

## 3. 训练 pipeline【已实现，尚未正式规模运行】

### 3.1 离线准备

| 步骤 | 输入 | 输出 | 状态 |
|---|---|---|---|
| ① 生成参考轨迹 | USIM | `data/refs/usim_{train,test}_v1` | 已完成 |
| ② 世界模型预训练（可选） | 训练集参考轨迹（状态 + `actions` 换算成策略动作） | `data/wm_refs/run1/world_model.pt`；测试集 1 秒开环位置误差 90% 分位 3 mm | 已完成 |

② 用的是与在线训练相同的世界模型更新方法（3.2 的 b），只是数据来自参考轨迹。

**正式训练默认不用 ②**，与原版一致（原版世界模型完全在线从零学）。理由：
- 离线拟合 50 次更新后，1 秒开环误差就从基线的 113 mm 降到 8 mm。在线训练这 50 次更新只要约 1.5 分钟，所以预训练最多省几分钟。
- 世界模型的输入归一化统计会在线累积更新：预训练的统计约 200 个真实步后就被在线数据冲淡。初期策略的动作幅度远小于参考轨迹（推进器标准差 0.5），归一化后的输入尺度会变 2–5 倍，预训练的权重恰好在最需要它的时候对不上。

② 的作用是验证世界模型能学会这套动力学，这一点已经确认。如果在线训练初期出现世界模型误差大、策略发散，再考虑用它初始化（`--runner.wm-init`），同时要冻结归一化统计。

### 3.2 在线训练循环 `rovmimic/train.py`

默认 4096 个仿真环境，与原版相同。每个真实步（所有环境各走一步）做 a 和 d，每 2.5 个真实步做一次 b 和 c。
更新频率 = 环境数 / (10 × 2048 × 8) × 16，即世界模型平均把每条转移用 16 次。默认训练 5 万个真实步，约 2 万次更新。

```
            ┌──────────────────── 每个真实步 ────────────────────┐
            │ a. 采集                                             │
            │    观测 → 加传感器噪声、用带误差的位置算 goal        │
            │    → 策略 → 动作 + N(0, 0.1) 探索噪声                │
            │    → 仿真环境 → 奖励、结束标志 → 存入回放缓存         │
            │ d. 记录回报，每 20 步更新重置分布                     │
            └──────────────────────────────────────────────────────┘
            ┌──────────────────── 每 2.5 个真实步 ─────────────────┐
            │ b. 世界模型更新：10 个小批 × 2048 段 × 8 步          │
            │ c. 策略更新：4096 个起点 × 想象 32 步，BPTT          │
            └──────────────────────────────────────────────────────┘
```

**a. 采集**（`ROVRunner.step`，真实仿真）

| | 内容 |
|---|---|
| 输入 | 当前观测、参考帧 t、环境的位置测量误差 |
| 处理 | 策略观测 = actor obs + 均匀噪声（半宽见 `system_overview.md` 1.7）；goal 用"真实位置 + 测量误差"算；动作 = 策略输出 + N(0, 0.1) |
| 输出 | 4096 条转移写入回放缓存；同时更新世界模型和策略的输入归一化统计 |

**b. 世界模型更新**（`WorldModelLearner`）

| | 内容 |
|---|---|
| 输入 | 从回放缓存抽 10 个小批，每批 2048 段、每段连续 8 步（段内没有回合结束）的 full_state 和动作 |
| 处理 | 从第 0 步的真实状态出发，用记录的动作在世界模型里连续滚 7 步，和第 1–7 步的真实状态比较 |
| 损失 | 按"名义误差"加权的均方误差：航行器位置 0.01 m、姿态 0.02 rad、机体系线速度 0.05 m/s、角速度 0.1 rad/s |
| 优化器 | Adam，学习率 2e-4，梯度范数裁剪 1.0 |
| 输出 | 更新后的世界模型 |

**c. 策略更新**（`ActorCriticPolicyLearner`）

| | 内容 |
|---|---|
| 输入 | 从回放缓存抽 4096 个真实状态作起点 |
| 处理 | 在想象环境（2.6）里滚 32 步。每步：策略看带噪声的观测出动作（不加探索噪声），世界模型推进，算奖励 r 和失败概率 p |
| 目标 | 回报 = Σ γᵗ·Sₜ·rₜ + γ³²·S₃₂·V(最后状态)，其中 Sₜ = Π(1 − p) 是存活概率，γ = 0.99 |
| 策略梯度 | 最大化回报，梯度沿 32 步反传，穿过世界模型、正运动学和奖励。Adam 学习率 2e-4，β₂ = 0.95；逐元素裁剪 0.1，范数裁剪 1.0 |
| 价值网络 | 用 GAE（λ = 0.95）算目标，均方误差，5 轮 × 4 个小批 |
| 输出 | 更新后的策略和价值网络 |

**存档和日志**：都在 `data/runs/logs/<任务名>/<时间>/` 下。W&B 默认离线。
- 每 1000 个真实步存一次 `actor.pt`、`world_model.pt`、`critic.pt`，覆盖上一次。
- 每 5000 个真实步另存一份到 `checkpoints/it_XXXXXXX/`，用来回头评估训练过程。
- 开始时写 `config.json`（完整配置），推理和评估按它重建网络。
- 每 10 步在控制台打印一次日志，`tools/plot_train_log.py` 可以画成曲线。

**批量规模**（默认值，与原版 SuperMimic 相同）：

| 部分 | 每次更新的批量 | 每次更新的梯度步 |
|---|---|---|
| 世界模型 | 10 个小批 × 2048 段 × 8 步，每个小批 16,384 个状态，合计 16.4 万条转移 | 10 |

## 4. 推理 pipeline

推理只用策略（`actor.pt`）。世界模型、价值网络、正运动学、奖励都不用。

| 部分 | 状态 | 位置 |
|---|---|---|
| 推理接口：读存档、算 goal、前向、换算成指令 | 【已实现】 | `rovmimic/policy.py`：`ROVPolicy`、`to_sim_command` |
| 导出成单文件（TorchScript / ONNX，输入 obs 36 + goal 230，输出动作 13） | 【已实现】与原网络输出一致 | `python -I rovmimic/policy.py export <存档目录> --onnx` |
| Stonefish 闭环评估（完成率、回报、误差，带或不带噪声） | 【已实现】 | `rovmimic/eval.py` |
| 可视化（曲线、3D 动画） | 【已实现】 | `tools/visualize_eval.py` |
| 真机 / ROS 部署节点 | 【未实现】 | — |

下面是策略需要的接口，按当前训练设定整理。

### 4.1 每 0.02 s 的输入

| 输入 | 来源 | 用途 |
|---|---|---|
| 重力方向（机体系） | IMU 的姿态估计（横滚、俯仰） | sensor |
| 机体角速度 | IMU 陀螺 | sensor |
| 机体线速度 | DVL | sensor |
| 7 个关节角 | 舵机编码器（两根手指可由夹爪换算） | sensor |
| 7 个关节角速度 | 由关节角差分：(q_k − q_{k−1}) / 0.02 | sensor |
| 上一步动作 | 策略自己上一步的输出（13 维，未截断） | actor obs |
| 当前位置 | 深度计（z）+ 水平定位（x、y） | 算 goal 的相对位置 |
| 当前姿态（含航向） | IMU + 航向估计 | 算 goal 的相对位置和相对姿态 |
| 参考轨迹 | 整条参考片段：每帧航行器位置、姿态、7 个关节角和角速度，50 Hz；当前帧号 t | 算 goal |

参考轨迹和当前位姿必须在同一个世界坐标系里。

### 4.2 处理

1. actor obs = [重力方向, 角速度, DVL 速度, 关节角, 关节角速度, 上一步动作]，共 36 维。不加噪声：真实传感器自带误差。
2. goal：用当前位姿和参考帧 t, t+5, …, t+45 按 1.3 计算，共 230 维。
3. 策略前向 → 13 维动作。
4. 换算成指令（1.4）：
   - 推进器设定值 clip 到 [−1, 1]；
   - 臂关节目标 = 当前角 + 0.01 × clip(a)；
   - 夹爪目标 = (clip(a) + 1)/2 × 0.015。
5. t += 1。到片段最后一帧后停住，或结束。

### 4.3 输出

8 个推进器设定值 [−1, 1]（顺序见 1.4），4 个臂关节目标角，1 个夹爪开合目标（两根手指由硬件或仿真按 0.83 倍联动）。

### 4.4 Stonefish 闭环评估 `rovmimic/eval.py`

| | 内容 |
|---|---|
| 输入 | 存档目录（`actor.pt` + `config.json`），或基线 `open_loop`（开环重放参考轨迹里记录的指令）；测试集参考轨迹 |
| 做法 | 每条片段一个环境，从片段第一帧开始按 4.2 闭环跟踪，到片段结尾或 `--max-seconds` 为止；触发失败（2.3）就停止计分 |
| 噪声 | 默认与训练相同：传感器噪声、位置测量误差、初始扰动都开。`--clean` 全关 |
| 输出 | `metrics.json`：完成率、失败原因、归一化回报，以及航行器位置 / 姿态、TCP、臂关节、夹爪误差的中位数和 90% 分位<br>`per_clip.csv`：每条片段一行<br>`rollouts.npz`：前几条片段的逐步轨迹，可视化用 |

开环基线在无扰动时与参考逐帧重合（回报 0.999、误差 0），这一点同时验证了评估本身。
加上训练时的初始扰动后，开环重放没有反馈会漂走：开发机上 8 条片段、20 s，完成率 50%，航行器位置误差中位数 22 cm。

`tools/visualize_eval.py` 画汇总图、每条片段的曲线图（位置、姿态、关节、误差、推进器），`--video` 时再生成 3D 动画，从状态经正运动学重建画面。
`tools/compare_evals.py` 把多次评估汇成一张表。

## 5. 建议审查的设计点

| # | 设计点 | 当前做法 | 可以考虑 | 改动位置 |
|---|---|---|---|---|
| 1 | 臂关节动作 | 相对目标 q + 0.01a，等于直接给速度 | — | `servo.py` |
| 2 | 探索噪声 | 13 维统一 N(0, 0.1) | 推进器和臂关节分开设 | `--runner.policy.noise` |
| 3 | 位置测量误差 | 水平：回合内漂移，最多 ±0.15 m；深度：±0.01 m | 量级要接近实际定位系统 | `env.py` `SensorNoiseCfg` |
| 4 | 航向误差 | **没有模拟**：goal 里的相对位置和姿态都用真实航向算 | 实际航向估计有几度误差，可以加 | `wm_env.py`、`runner.py` 的测量位姿 |
| 5 | DVL | 每步都有读数 | 实际 5 Hz、会丢数 | `SensorNoiseCfg` |

| 7 | 参考窗口 | 未来 0.9 s，10 帧，间隔 5 帧（与原版相同） | 航行器慢，窗口可能要更长 | `state.py` |
