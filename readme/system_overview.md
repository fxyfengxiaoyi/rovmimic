# 水下机器人全身轨迹跟踪：系统说明

本文说明我们要控制的机器人由什么组成，参考轨迹里有什么，以及 SuperMimic 怎样用这些数据训练控制策略。

标注说明：**【已实现】** 表示代码已经写好并验证过；**【计划】** 表示还没实现，是目前的设计方案，可以调整。

最后更新：2026-11-16。

---

## 0. 一页总览

```
机器人  = BlueROV2 Heavy 航行器（6 自由度，8 个推进器）
        + Reach Alpha 5 机械臂（4 个转动关节）
        + Robotiq Hand-E 夹爪（1 个开合自由度，两根手指）

参考轨迹 = USIM 数据集里的推进器指令，在 Stonefish 里重放得到的“全身状态”序列，50 Hz
          （航行器位姿和速度 + 7 个关节的角度和速度，外加末端位姿）

策略    输入：IMU、关节编码器、DVL 速度、相对参考位置的偏差 + 未来约 1 秒的参考轨迹
        输出：8 个推进器指令 + 4 个臂关节的相对目标 + 1 个夹爪开合目标，50 Hz

世界模型 学习“给了这些指令，航行器下一步速度会怎么变”，只预测 6 个数
        机械臂怎么动（舵机规律已知）、位置怎么积分、手在哪里、奖励多少，全部用公式算
```

## 1. 机器人由什么组成

### 1.1 坐标系

| 坐标系 | 约定 |
|---|---|
| 世界系 | NED：x 指北、y 指东、**z 向下**。z 就是深度，越大越深 |
| 机体系（航行器） | FRD：x 向前、y 向右、**z 向下** |
| 航行器位姿的参考点 | `base_link` 坐标系的原点。注意它不是质心；质心离原点几厘米 |

所有位置单位是米，角度单位是弧度，四元数按 `w, x, y, z` 的顺序存储。

### 1.2 航行器：BlueROV2 Heavy

| 项目 | 数值 |
|---|---|
| 艇体质量 | 11.68 kg |
| 艇体排水体积 | 12.69 L，浮力约 128.3 N |
| 整机质量（含机械臂） | 13.08 kg，重力约 128.3 N |
| 结果 | **中性浮力**：不推也不浮不沉。重心与浮心不完全对齐：静止时艇体低头约 2°，机械臂伸到 armed 姿态时约 4° |
| 自由度 | 6 个：前后、左右、上下平移，加上横滚、俯仰、偏航转动 |
| 是否全驱动 | 是。8 个推进器可以独立控制全部 6 个自由度 |

**8 个推进器**。顺序固定，策略输出和参考轨迹里的 `actions` 都按这个顺序：

| 序号 | 名称 | 位置（机体系，m） | 推力方向 | 主要作用 |
|---|---|---|---|---|
| 0 | FrontRight（FR） | (0.136, 0.10, 0.073) | 水平，斜 45° | 前进/后退、横移、转向 |
| 1 | FrontLeft（FL） | (0.136, -0.10, 0.073) | 水平，斜 45° | 同上 |
| 2 | BackRight（BR） | (-0.148, 0.10, 0.073) | 水平，斜 135° | 同上 |
| 3 | BackLeft（BL） | (-0.148, -0.10, 0.073) | 水平，斜 135° | 同上 |
| 4 | DiveFrontRight（DFR） | (0.12, 0.218, 0) | 竖直 | 上浮/下潜、横滚、俯仰 |
| 5 | DiveFrontLeft（DFL） | (0.12, -0.218, 0) | 竖直 | 同上 |
| 6 | DiveBackRight（DBR） | (-0.12, 0.218, 0) | 竖直 | 同上 |
| 7 | DiveBackLeft（DBL） | (-0.12, -0.218, 0) | 竖直 | 同上 |

- 指令范围是 **[-1, 1]**，负值表示反转。USIM 里记录的 `pwm` 字段就是这个值，可以直接使用。
- 推力大小：指令 0.5 时每个推进器约 5 N。推力与转速的平方成正比，所以指令 1.0 时约 20 N（这是推算值）。
- 速度响应比较慢：4 个水平推进器一起推，10 s 后才到约 0.29 m/s，时间常数 3–4 s。这是水的阻力和附加质量造成的。

### 1.3 机械臂：Reach Alpha 5

机械臂装在艇体**前方、左侧、下方**，安装座在机体系 (0.196, -0.084, 0.145) m 处。

```
艇体 ── 安装座 ── 基座旋转(e) ── 肩(d) ── 大臂 ── 肘(c) ── 小臂 ── 腕部旋转(b) ── 夹爪
```

**4 个臂关节**，都是转动关节，由位置舵机驱动：

| 关节 | 作用 | 转轴 | 允许范围（rad） | 舵机最大速度 |
|---|---|---|---|---|
| `axis_e` | 基座旋转：整条臂绕安装轴转 | 绕臂的安装轴 | 0 – 6.10 | 0.5 rad/s |
| `axis_d` | 肩：大臂抬起或放下 | 侧向轴 | 0 – 3.49 | 0.5 rad/s |
| `axis_c` | 肘：小臂弯曲 | 侧向轴 | 0 – 3.22 | 0.5 rad/s |
| `axis_b` | 腕部旋转：夹爪绕小臂转 | 沿小臂轴 | 0 – 3.22 | 0.5 rad/s |

- 舵机的行为：给定目标角度后，以最大速度匀速转过去，到了就停，最大力矩 9 N·m。按控制步算，就是**每个 0.02 s 控制步里关节朝目标最多走 0.01 rad**，细节见下面的“舵机的逐步行为”。
- 场景文件里写了关节限位，但写法 Stonefish 不识别，**仿真里限位实际不生效**。
  - 原因：场景文件写的是 `<limit lower upper>`，解析器读的是 `<limits min max>`；读不到时用默认值 (1, −1)，`AddJointLimit` 发现下限大于上限就直接跳过。
  - 2026-11-16 实测：目标设到限位外，所有关节（包括两根手指）都会走过去。
  - 限位要靠我们自己保证：生成随机动作时只在限位内采样，训练策略时用奖励惩罚超限（见 4.5）。
- **机械臂和艇体之间也不做碰撞检测**：场景里 `self_collisions="false"`，机械臂可以穿过艇体。参考轨迹生成时检查过不碰艇体，策略训练时用正运动学算出机械臂上的检查点，进入艇体包围盒就惩罚（见 4.5）。
- 两个常用姿态：
  - **初始姿态**：全 0，机械臂收拢。
  - **armed 姿态**：b = c = 0.50，d = 0.51，e = 0，机械臂伸到艇体前下方，准备抓取。USIM 抓取任务 98% 的时间停在这个姿态。

**舵机的逐步行为**（2026-11-14 用 sfenv 实测）。机械臂停在 armed 姿态，每一步都把 `axis_d` 的目标设在当前角度前方 δ 处：

| δ（rad） | 实际平均速度（这一步的位移 / 0.02 s） | 步末读到的关节角速度 |
|---|---|---|
| 0.001 | 0.05 rad/s | 0 |
| 0.003 | 0.15 rad/s | 0 |
| 0.005 | 0.25 rad/s | 0 |
| 0.008 | 0.40 rad/s | 0.30 rad/s |
| ≥ 0.01 | 0.50 rad/s（饱和） | 0.50 rad/s |

原因在 Stonefish 的 `Servo::Update`：目标误差大于“最大速度 × 物理步长”（0.5 × 0.01 = 0.005 rad）时，舵机以最大速度转；误差小于这个值时，切成位置模式，在一个物理步内到位并停住。一个控制步有 2 个物理步，所以：

- 目标离当前角度不超过 0.01 rad 时，这一步就能走到目标，速度可以在 0 到 0.5 rad/s 之间调节；**目标再远，效果都一样**，就是以 0.5 rad/s 转。
- 这一步内走到目标时，**步末读到的角速度是 0**，不反映这一步实际动了多少。

这两点分别影响策略输出（见 4.2）和世界模型的积分（见 4.4）。

**2026-11-16 复核**（`tools/check_servo_model.py`）：
- 上表完全复现。
- 每个控制步的位移严格等于 `clip(目标 − 当前角度, ±最大速度 × 0.02 s)`，误差不超过 4e-7 rad。测试了 300 段随机运动，其中 1/3 是机械臂水平伸出、满速来回换向，同时推进器随机满量程，力矩上限（9 N·m）从未饱和。夹爪 `axis_a`（0.18 rad/s）和两根手指（0.15 m/s）同样成立。
- 所以机械臂和夹爪的运动可以完全用这个公式计算（见 4.4）。

**连杆**：仿真里一共 12 个连杆，包括艇体：

| 连杆 | 质量 | 说明 |
|---|---|---|
| `base_link` | 11.68 kg | 艇体 |
| `ArmBaseLink` | ≈0 | 安装座，固定在艇体上 |
| `m3_inline_link` | 0.341 kg | 臂的基座段，固定在安装座上 |
| `m2_1_1_link` | 0.194 kg | 随 `axis_e` 转 |
| `m2_joint_link` | 0.429 kg | 大臂，随 `axis_d` 转 |
| `m2_1_2_link` | 0.115 kg | 小臂，随 `axis_c` 转 |
| `m1_link` | 0.200 kg | 腕部，随 `axis_b` 转 |
| `ee_base_link` | ≈0 | 夹爪安装面，MoveIt 规划用的末端 |
| `EEBaseLink` | 0.108 kg | Robotiq 夹爪本体，与 `ee_base_link` 重合 |
| `push_rod` | ≈0 | 占位连杆，随 `axis_a` 转，不影响任何东西 |
| `rs1_130_link` / `rs1_139_link` | 各 0.005 kg | 两根手指 |

整条臂加夹爪共约 1.4 kg，伸出去时会明显推动艇体：同样的推进器指令，机械臂随机运动 10 s 后，艇体位置偏开的中位数约 4 cm，最多约 29 cm。

### 1.4 夹爪：Robotiq Hand-E

- 两根手指各自沿直线滑动（移动关节 `rs1_130_joint`、`rs1_139_joint`），每根行程 0–12.5 mm。
- 开合由一个指令 `axis_a` 控制：0 是张开，0.015 是闭合。两根手指的目标都是 0.83 × `axis_a`，这是 U0 的约定。
- **TCP（末端点）** 定义为 `ee_base_link` 沿夹爪接近方向 7.5 cm 处，也就是抓取时物体中心所在的位置。各个特征点沿接近方向的距离：

| 点 | 距 `ee_base_link` 原点 |
|---|---|
| `ee_base_link` 原点：夹爪根部，MoveIt 规划用的末端 | 0 cm |
| 手指关节 | 4.95 cm |
| 指垫范围 | 4.7 – 8.2 cm |
| **TCP：抓取时物体中心** | **7.5 cm**（USIM 数据反推中位数 7.4 cm） |
| 指尖，只用于防碰撞检查 | 8.5 cm |

### 1.6 仿真里的“水”

物理引擎是 Stonefish：物理计算 100 Hz，控制 50 Hz，即每个控制步算 2 个物理步。

| 有 | 没有 |
|---|---|
| 艇体浮力 | 洋流（USIM 里没有，我们也不加） |
| 艇体的水阻力（按网格每个三角面计算） | 机械臂和夹爪受到的任何水的作用（U0 的模型就是这样，臂段只受重力） |
| 艇体的附加质量（加速时要额外推动周围的水） | 海底接触、水面效应（我们的场景里没有海底；贴近水面的片段已经处理掉） |
| 机械臂运动对艇体的反作用力 | |

### 1.7 传感器

USIM 数据集里记录的是真实风格的传感器读数：DVL 测机体速度（5 Hz），IMU 测角速度和比力（20 Hz），还有深度计。

**训练时策略看到的"传感器"读数 = 真实状态换算 + 模拟的误差**【已实现】，`rovmimic/state.py`（换算）、`rovmimic/env.py` 的 `SensorNoiseCfg`（误差）。我们不在 Stonefish 里挂传感器对象，原因有两个：
- 策略训练大部分在世界模型里"想象"进行，那里没有 Stonefish。读数必须能由预测状态用公式算出，这样仿真和世界模型两边一致，梯度也能传过去。
- SuperMimic 原版处理 IMU、关节编码器也是这样做的，两边共用同一套噪声设置。

| 读数 | 换算方式 | 模拟的误差（第一版） |
|---|---|---|
| 重力方向（IMU） | 姿态换到机体系 | 每步均匀噪声 ±0.02 |
| 角速度（IMU） | 换到机体系 | ±0.05 rad/s。原版人形是 ±0.2，但航行器角速度 95% 分位才 0.24 rad/s，按比例缩小 |
| 关节角度（编码器） | 状态里的值 | ±0.005 rad |
| 关节角速度 | 上一步平均速度 | ±0.05 rad/s。臂关节最快才 0.5 rad/s，原版的 ±0.5 太大 |
| 机体速度（DVL） | 线速度换到机体系 | ±0.02 m/s |
| 竖直位置（深度计） | 当前深度 | 每步独立 ±0.01 m，不漂移 |
| 水平位置（定位） | 当前 x、y | 回合开始时偏差在 ±0.05 m 内均匀取，之后每步随机游走（标准差 0.002 m），上限 ±0.15 m；10 s 回合约漂 5 cm。模拟 DVL 积分定位的累积误差 |

位置读数不直接给策略，而是用来算"参考位置相对当前位置在哪"（见 4.2）。世界模型里每段想象只有 0.64 s，期间漂移可以忽略，所以每段开始时在 ±0.1 m 内抽一个固定偏差。

DVL 实际 5 Hz 更新、偶尔丢数，第一版先不模拟，后面再加。

只在验证"仿真能不能复现 USIM"时，我们才按 USIM 的传感器定义换算读数，和 USIM 记录对比。

## 2. 状态向量（27 维）【已实现】

仿真接口 `sfenv` 读写的状态、参考轨迹存的数据，以及世界模型使用的状态，都是这一套：

| 下标 | 内容 | 维数 |
|---|---|---|
| 0–2 | 航行器位置（世界系，`base_link` 原点） | 3 |
| 3–6 | 航行器姿态，四元数 wxyz | 4 |
| 7–9 | 航行器线速度（世界系，原点的速度） | 3 |
| 10–12 | 航行器角速度（世界系） | 3 |
| 13–19 | 7 个关节角度 | 7 |
| 20–26 | 7 个关节角速度 | 7 |

关节顺序是 `axis_e, axis_d, axis_c, axis_b, axis_a, rs1_139_joint, rs1_130_joint`，与 Stonefish 内部顺序一致，参考轨迹的 `joint_names.json` 里也是这个顺序。

## 3. 参考轨迹

### 3.1 怎么来的【已实现】

USIM 数据集只记录了传感器读数和推进器指令，**没有世界系位置**，不能直接当参考轨迹用。我们的做法是：

1. 取 USIM 一条 episode 的第 0 帧构造初始状态：深度来自深度计，横滚和俯仰来自 IMU，速度来自 DVL。USIM 没有偏航和水平位置，就设为 0。
2. 把记录的推进器指令从 10 Hz 补到 50 Hz（每条指令保持 0.1 s），在 Stonefish 里从头到尾重放。
3. 记录重放过程中每一帧的完整状态，得到参考轨迹。

这样得到的轨迹天然是"这台机器人在这个仿真里真的能走出来的"。我们验证过重放结果和 USIM 记录的速度、角速度、深度都对得上：导航任务速度误差中位数约 4%。

每条 USIM episode 生成**两条**参考轨迹，推进器指令完全相同：

| 版本 | 机械臂怎么动 | 为什么要它 |
|---|---|---|
| `usim` | 复刻 USIM 记录的关节运动 | 保持与原数据一致 |
| `random` | 在关节限位内随机点到点运动，夹爪随机开合，保证不碰艇体 | USIM 里机械臂几乎不动：导航任务完全不动，抓取任务 98% 时间停在 armed 姿态。没有这一版，策略学不到"手臂在动时怎么稳住艇体" |

`random` 版里机械臂的反作用会推动艇体，所以它的航行器轨迹也和 `usim` 版略有不同。这是物理仿真的真实结果，仍然一致、可行。

数据清洗：
- 跳过 USIM 里明显异常的 episode：开头就翻倒、关节速度超过舵机极限很多、关节角跳变、角速度异常。
- 贴着水面走的 episode 整体下移到至少 0.6 m 深；重放后仍浅于 0.3 m 的丢弃。

### 3.2 每一帧有哪些分量【已实现】

格式与 SuperMimic 使用的 mjlab 打包格式相同，每个字段一个 `.npy` 文件，所有片段首尾相接：

| 字段 | 维数 | 含义 | 训练时谁用 |
|---|---|---|---|
| `root_pos_w` | 3 | 航行器位置 | 跟踪目标 |
| `root_quat_w` | 4 | 航行器姿态 | 跟踪目标 |
| `root_lin_vel_w` | 3 | 航行器线速度 | 跟踪目标 |
| `root_ang_vel_w` | 3 | 航行器角速度 | 跟踪目标 |
| `joint_pos` | 7 | 关节角度 | 跟踪目标 |
| `joint_vel` | 7 | 关节角速度 | 跟踪目标 |
| `actions` | 15 | 产生这一帧的指令：8 推进器 + 7 舵机 | 跟踪时不用；可用来预训练世界模型（见 4.3） |
| `ee_pos_w` / `ee_quat_w` | 3 / 4 | TCP 位姿，由 Stonefish 算出 | 只用来校验正运动学；训练时 TCP 由正运动学从前 6 项算出 |

另外还有：
- `motion_ends.npy`：每条片段在哪一帧结束；
- `motion_names.json`：片段名，如 `ep00030_usim`；
- `joint_names.json`：关节顺序；
- `meta.json`：每条片段的来源 episode、任务、机械臂模式、随机种子，以及被跳过的 episode 和原因。

**关键点**：参考轨迹真正需要的只有前 6 项，即航行器的位姿和速度、关节的角度和角速度。末端在哪、每个连杆在哪，都可以由正运动学从这 6 项算出来。

- 平均每条片段约 40 s。
- v1（2026-11-16）与 v0 内容相同，只是关节角速度改为“上一步平均速度”；v0 已删除。
- 跳过的原因：重放后过浅 36 条，开头姿态异常 4 条，角速度异常 4 条。
- 航行器速度中位数 0.03 m/s，p95 约 0.63 m/s，大部分时间在悬停或慢速移动。

## 4. SuperMimic 怎样训练策略

### 4.1 整体循环

SuperMimic 的核心想法：**策略不在真实仿真器里学，而是在学到的世界模型里学**。世界模型可微，奖励对策略参数的梯度可以直接沿时间反传（BPTT），比强化学习的试错高效得多。真实仿真器只用来采集数据、校正世界模型。

```
① 采集        在 Stonefish 里跑当前策略（加一点随机噪声），
              记录 (状态, 动作, 下一状态)，存进回放缓存
      │
      ▼
② 训练世界模型  从缓存取 8 步长的真实片段，用记录的动作在世界模型里滚 8 步，
              让预测的状态尽量贴近真实状态
      │
      ▼
③ 训练策略     从缓存取起点，在世界模型里“想象”策略跑 32 步（0.64 s），
              每步算跟踪奖励，梯度沿 32 步反传更新策略
      │
      └──────→ 回到 ①，反复进行
```

每个回合从参考轨迹的某一帧开始，把仿真设成那一帧的状态。哪些片段策略跟得差，就更多地从那里开始。

### 4.2 策略：输入与输出【已实现】

**输出**（每 0.02 s 一次）：

| 分量 | 维数 | 说明 |
|---|---|---|
| 推进器指令 | 8 | [-1, 1]，顺序见 1.2 |
| 机械臂舵机目标 | 4 | e、d、c、b 的目标角度，**相对当前角度给出**，见下 |
| 夹爪开合目标 | 1 | `axis_a`，两根手指的目标自动换算成 0.83 × a |

这和 USIM 的 `action` 布局（5 个关节 + 8 个推进器）一致。

**臂关节目标用相对量**。SuperMimic 原版把动作当成绝对目标：`目标 = 动作 × scale + 默认姿态`。我们的舵机每步最多走 0.01 rad（见 1.3）。目标一旦比当前角度远出 0.01 rad，再远效果都一样，下一步的状态对这个动作的梯度就是 0，BPTT 传不回来。绝对目标的取值范围有几个弧度，绝大部分都落在这个饱和区里。所以改成：

```
目标 = 当前角度 + 0.01 × a，a ∈ [-1, 1]
```

这样整个动作范围都对应 0 到 0.5 rad/s 之间的有效速度，梯度处处存在。

- 世界模型直接输入 a；换算成绝对目标只在仿真环境一侧做。
- USIM 和参考轨迹的 `actions` 里存的是绝对目标。用它们预训练世界模型时，要先换算成 `a = clip((目标 − 当前角度) / 0.01, −1, 1)`。截断不丢信息，因为超出 0.01 rad 的部分本来就不起作用。
- 夹爪 `axis_a` 的全行程只需约 4 步（0.015 / 0.18 rad/s ≈ 0.08 s），基本只有开、合两种状态，保持绝对目标：a ∈ [−1, 1] 线性映射到 0–0.015。
- 推进器指令 a ∈ [−1, 1] 直接下发。

**输入**：

| 分量 | 来源 | 说明 |
|---|---|---|
| 重力方向（机体系） | IMU | 告诉策略自己倾斜了多少 |
| 角速度 | IMU | |
| 关节角度、关节角速度 | 舵机编码器 | |
| 上一步的动作 | 自己 | |
| 未来 0.9 s 的参考关节角度和角速度 | 参考轨迹 | 取当前帧起每隔 5 帧一个，共 10 帧 |
| 未来 0.9 s 的参考航行器姿态（相对当前姿态） | 参考轨迹 | 同样 10 帧 |
| **新增**：机体速度 | DVL | 推力需求取决于当前速度（水阻力、附加质量）；航行器悬浮在水里，没法像人形机器人那样从腿的运动推算出速度 |
| **新增**：未来 0.9 s 的参考航行器位置（相对当前位置，机体系） | z：深度计；x、y：定位 | 同样 10 帧。水下轨迹跟踪的核心反馈，读数误差见 1.7 |

维数：传感器 23（重力 3、角速度 3、DVL 3、关节角 7、关节角速度 7）+ 上一步动作 13 = 36；参考窗口 10 帧 ×（关节角 7 + 关节角速度 7 + 相对位置 3 + 相对姿态 6）= 230。价值网络看到的是真实状态和不带误差的参考窗口。

**为什么人形机器人原版不给位置偏差，我们要给**：
- 奖励本来就要用位置偏差，但奖励只在训练时算，用的是仿真真值（或世界模型的预测），不需要机器人自己测量。问题在于部署时策略能不能看到这个偏差。
- SuperMimic 原版的策略看不到：这一项只给世界模型和价值网络，导出策略时按名字删掉。BeyondMimic 有个开关，打开时给策略，部署靠状态估计提供。
- 人形机器人能接受这一点，有两个原因：
  - 它的连杆奖励在比较前，先把参考动作平移、旋转到机器人当前的水平位置和朝向，只比"姿势像不像"；只有一项权重较低的全局位置奖励管漂移。
  - 漂移几十厘米可以接受，而且姿势做对了，位移大体也跟着对了。
- 我们的位置本身就是任务：末端要到达物体，偏 30 cm 就抓不到。航行器也没有腿，姿势对了不会带来位移。所以必须把位置偏差反馈给策略。U0 也是这样做的：它给策略的 `target_pos` 就是用仿真真实定位算出的相对位置。

### 4.3 世界模型：用什么数据训练、预测什么

**训练数据**：
- 主要来源是第 ① 步在 Stonefish 里实时采集的数据：每一帧的 27 维状态、策略给出的动作，以及接下来的真实状态。数据随训练不断更新，始终接近当前策略会遇到的情况。【已实现】
- 参考轨迹本身也是 Stonefish 的真实转移数据：存了状态和产生它的 `actions`，共 10 多个小时，可以在训练开始前用来预训练世界模型。【计划】
- USIM 原始数据不直接用于训练世界模型。世界模型需要 50 Hz 的完整状态，USIM 只有 10 Hz，而且缺世界系位置和偏航。USIM 的信息已经通过重放进入了参考轨迹。

**世界模型（一个神经网络）每步做的事**：

```
输入：当前状态的“身体部分”      动作（13 维，臂关节是相对量）
      [深度, 重力方向, 机体速度,
       机体角速度, 关节角, 关节角速度]
                  │                  │
                  └────────┬─────────┘
                           ▼
                   神经网络（MLP）  ← 可选：仿真参数（如随机化的质量、浮力），SuperMimic 支持，初版不用
                           ▼
输出：航行器下一步速度的变化量（共 6 个数）
      机体线速度变化(3) + 机体角速度变化(3)
```

网络**只预测航行器的速度怎么变**，因为这部分包含了推进器推力、水的阻力和附加质量、机械臂反作用力，这些复杂的动力学需要学习。机械臂和夹爪的运动规律已经实测验证（见 1.3），直接用公式算。其余所有东西也都由公式算出。

SuperMimic 原版的网络还要预测关节角速度的变化（人形机器人共 6 + 29 个数），对我们来说这部分是多余的。

**训练目标**【已实现】：从缓存取一段 8 步的真实数据，用记录的动作在世界模型里连续滚 7 步，和真实状态比较。比较的量和各自的"名义误差"（误差除以它再平方，相当于权重）：

| 比较的量 | 名义误差 | 和原版的区别 |
|---|---|---|
| 航行器位置 | 0.01 m | 同原版 |
| 航行器姿态 | 0.02 rad | 同原版 |
| 机体系线速度 | 0.05 m/s | 新增。DVL 速度是策略的输入，速度项也进奖励，直接监督更稳 |
| 机体系角速度 | 0.1 rad/s | 新增，理由同上 |
| 关节角度、角速度 | — | 原版有，我们去掉：关节由公式算，没有可学的东西 |

网络输入的动作先截断到 [−1, 1]，与仿真里实际生效的一致。

**网络输出乘一个固定尺度**【已实现】：速度变化量 = 网络输出 × (0.002, 0.002, 0.002) m/s、(0.004, 0.002, 0.01) rad/s，取参考轨迹里每步速度变化的标准差量级。原版没有这一项。原因：
- 这台航行器在仿真里很重（平移等效约 166 kg），每步速度只变 0.001–0.007 m/s。
- 网络直接输出时，Adam 每次更新带来的输出抖动约 0.01，比信号还大。
- 原版人形每步速度变化 0.1–1 m/s，所以不受影响。

**离线检查**【已实现】，`tools/fit_wm_refs.py`：用训练集参考轨迹的真实状态和动作训练世界模型（原版的训练方法和网络大小，6000 个小批，约 4 分钟），在测试集上从真实状态出发、用真实动作连续滚 50 步（1 秒），和真实轨迹比较。基线是"速度保持不变"。

| 第 50 步的误差（90% 分位） | 基线 | 输出不加尺度 | 输出加尺度 |
|---|---|---|---|
| 位置 | 113 mm | 302 mm | **3.0 mm** |
| 姿态 | 0.108 rad | 0.057 rad | **0.008 rad** |
| 机体速度 | 0.224 m/s | 0.483 m/s | **0.006 m/s** |
| 机体角速度 | 0.165 rad/s | 0.089 rad/s | **0.013 rad/s** |

- 不加尺度时，训练损失在降，测试结果却比基线还差，而且每次评估波动很大。
- 加尺度后误差稳定下降，600 轮时还在缓慢下降。
- 训练好的世界模型存在 `data/wm_refs/run1/world_model.pt`，正式训练可以用 `--runner.wm-init` 从它开始。
- 参考轨迹里的推进器指令来自 USIM（多为脉冲后滑行），机械臂是随机点到点运动。策略学到的动作分布会不同，所以正式训练时世界模型仍要用在线采集的数据继续学。

### 4.4 哪些是网络预测，哪些是解析计算（核心）

| 量 | 怎么得到 | 说明 |
|---|---|---|
| 下一步机体线速度、角速度 | **网络预测**（预测变化量，加到当前值上） | 动力学：推力、水阻力、附加质量、手臂反作用 |
| 下一步航行器位置、姿态 | **解析：积分** | 位置 += 速度 × 0.02 s，姿态按角速度转动。在参考轨迹上验证：位置误差中位数 1.6e-7 m，姿态 5.6e-8 rad |
| 下一步关节角度 | **解析：舵机公式** | 臂关节 `q + 0.01 × a`；夹爪和手指 `q + clip(目标 − q, ±最大速度 × 0.02 s)`。见表后 |
| 下一步关节角速度 | **解析：舵机公式** | 定义为这一步的平均速度 Δq / 0.02 s，见表后 |
| 深度、重力方向 | **解析** | 由位置、姿态直接得到 |
| 各连杆和 TCP 在世界系的位姿和速度 | **解析：正运动学** `rovmimic/fk.py` | 由航行器位姿和关节角，按机械臂几何逐级推算。【已实现】，与 Stonefish 误差 1e-14 m |
| 参考轨迹的连杆和 TCP 位姿 | **解析：正运动学**（同一个） | 预测和参考用完全相同的方法计算 |
| 奖励 | **解析** | 比较上面两项的差距，见 4.5 |
| 回合是否失败 | **解析** | 航行器**三维位置**或姿态偏离参考过大、机械臂进入艇体，就判失败（平滑版本，便于求梯度）。原版只看高度和倾斜，水平偏多远都不算失败，对我们不适用 |
| 策略看到的“传感器”读数 | **解析** | 由预测状态换算出重力方向、角速度、关节角、DVL 速度、相对参考位置的偏差，再加模拟误差（见 1.7） |

**为什么机械臂和夹爪不用原版的积分公式**。舵机在一个控制步之内就走到目标时，步末读到的角速度是 0，但关节其实动了。见 1.3 的表：δ = 0.003 时每步动 0.003 rad，读数却是 0。SuperMimic 原版的积分公式是：

```
角度 += (当前角速度 + 0.75 × 角速度变化) × 0.02 s
```

如果一步前后的角速度读数都是 0，这个公式算出来关节不动，和实际不符。

用这个公式检查了现有参考轨迹的 4 个臂关节（2026-11-16 在训练集上复核，结果相同）：
- 在关节有运动的帧里，误差中位数 1e-8 rad，2.5–3.0% 的帧误差超过 1 mrad，最大 5 mrad。
- 超过 1 mrad 的帧全部在每段运动起步或停下的那一两步。

参考轨迹里的机械臂总是以最大速度点到点运动，所以误差不大。但策略一旦学会用小目标精细控制关节，这种情况就会大量出现。

**采用的做法：机械臂和夹爪完全用公式**【已实现】，`rovmimic/terms.py` 的 `arm_step`：

```
臂关节（e、d、c、b）：q_next = q + 0.01 × a              a ∈ [−1, 1] 是策略输出的相对目标
夹爪 axis_a、两根手指：q_next = q + clip(目标 − q, ±最大速度 × 0.02 s)
关节角速度：         qd_next = (q_next − q) / 0.02 s       即这一步的平均速度
```

- **成立的前提已验证**：舵机力矩从不饱和，公式与仿真的误差不超过 4e-7 rad（见 1.3）。
- **好处**：
  - 臂关节对动作的梯度恒为 0.01，4.2 的梯度问题和这里的积分问题一起解决；
  - 网络只需要学航行器的 6 个速度变化。
- **机械臂对艇体的反作用仍由网络学**：网络的输入里有这一步的动作，也就知道机械臂这一步动了多少。
- **配套修改**：
  - 关节角速度统一采用"上一步的平均速度"这个定义，不用仿真的步末读数。
  - 在仿真里采集数据时，按 Δq / 0.02 s 计算关节角速度。
  - 参考轨迹的 `joint_vel` 也按同一定义重新计算，生成 v1 版。否则奖励里的关节速度项、连杆速度项会和预测对不上。

一句话概括：**网络只学 6 个数，即航行器下一步速度怎么变；机械臂运动、位置、末端位置、奖励全部是公式。** 所以世界模型简单、不容易学偏，而且末端位置一定与关节角一致。

梯度的路径：

```
奖励 ← 末端误差 ← 正运动学 ← 航行器位姿 ← 积分 ← 网络预测的速度变化 ← 推进器动作 ← 策略
                          ↖ 关节角 ← 舵机公式 ← 臂关节动作 ← 策略
```

每一环都可微，策略能直接知道"末端低了 3 cm，应该怎样调推进器和关节"。

### 4.5 奖励和失败判定【已实现】

`rovmimic/tracking.py`。仿真环境用 Stonefish 的真实状态算，世界模型用预测状态算，**调用的是同一个函数**，所以同一个状态在两边得到的奖励和判定完全相同。原版在仿真一侧（mjlab）和世界模型一侧各写了一份，靠人工保持一致。

**奖励**：跟踪项的形式是 `权重 × exp(−误差² / std²)`，误差为 0 时得满分；惩罚项是 `权重 × 惩罚量`，权重为负。每步奖励 = 0.02 s × 各项之和，满分 0.16。

| 奖励项 | 比较什么 | 权重 | std | 和原版的区别 |
|---|---|---|---|---|
| 航行器位置 | `base_link` 世界系位置 | 1.0 | 0.3 m | 权重 0.5 → 1.0：位置本身就是任务 |
| 航行器姿态 | 姿态转角（含偏航） | 0.5 | 0.4 rad | 同原版 |
| 臂上连杆位置 | 5 个点*，参考先整体对齐到当前航行器的位置和姿态再比 | 1.0 | 0.1 m | 原版只对齐水平位置和偏航，std 0.3 m。我们按 6 自由度对齐，这一项只比"机械臂摆得像不像"；臂长不到 0.5 m，std 收紧到 0.1 m |
| 臂上连杆姿态 | 同上 | 1.0 | 0.4 rad | 同上 |
| 连杆线速度 | 航行器 + 5 个点，世界系 | 1.0 | 0.3 m/s | std 1.0 → 0.3：水下速度小得多 |
| 连杆角速度 | 同上 | 1.0 | 1.0 rad/s | std 3.14 → 1.0，同上 |
| **TCP 位置** | 世界系直接比，**不对齐** | 2.0 | 0.1 m | 新增。对齐会把"航行器漂了，所以末端偏了"这个误差抹掉，而它正是抓取最关心的 |
| **夹爪开合** | `axis_a` | 0.5 | 3 mm | 新增。夹爪行程只有 15 mm，在连杆位置项里看不出来 |
| 动作变化惩罚 | Σ(本步动作 − 上步动作)² | −0.1 | | 同原版 |
| **动作越界惩罚** | Σ(超出 [−1, 1] 的部分)² | −1.0 | | 新增。动作超出范围的部分不起作用、也没有梯度，策略一旦跑出去就回不来，要靠它拉回 |
| 关节超限惩罚 | 超出 1.3 表中范围的量 | −10 | | 原版 −2。仿真里限位不生效，加重 |
| **机械臂侵入艇体** | 检查点进入艇体包围盒的深度 | −20 | | 新增。仿真不做机械臂与艇体的碰撞检测 |

\* 5 个点：每个臂关节之后的第一个连杆（`m2_1_1_link`、`m2_joint_link`、`m2_1_2_link`、`ee_base_link`）和 TCP。

在参考轨迹上自检：仿真执行参考轨迹存的动作时，所有跟踪项都是满分 1.0，只有动作变化惩罚在扣分（参考轨迹里机械臂满速点到点运动，换向的那一步动作从 −1 跳到 +1）。

**失败判定**（回合提前结束）：

| 条件 | 阈值 | 和原版的区别 |
|---|---|---|
| 航行器三维位置偏离参考 | 0.5 m | 原版只看高度，阈值 0.25 m |
| 航行器姿态偏离参考（转角，含偏航） | 0.8 rad | 原版只看倾斜 |
| 机械臂侵入艇体 | 3 cm | 新增 |
| 仿真数值发散 | | 新增保护 |

片段放完、或回合满 10 s，算正常结束（不算失败）。世界模型里用平滑版本：`sigmoid((max(各项误差 / 阈值) − 1) / 0.05)`，形式与原版相同。

**回合开始的状态**：按 SuperMimic 原版的"按回报采样"，回报低的参考片段段落被采到的概率更高，从参考轨迹的某一帧开始，加小扰动：位置 ±5 cm，横滚和俯仰 ±0.05 rad，偏航 ±0.1 rad，线速度 ±0.05 m/s，角速度 ±0.05 rad/s，臂关节 ±0.05 rad。夹爪不加扰动。
